# Proposal

## Why

letsmall 已能通过官网分发安装包，但已安装的客户端无法发现新版本或在软件内更新。需要让用户在启动软件或打开更新界面时收到新版本提示，并主动点击完成升级。

## What Changes

- 仅在每次应用启动和每次打开更新界面时异步检查更新；不定时轮询、不后台常驻、不在软件退出后推送。
- 新增英文更新界面，展示当前版本、最新版本、更新说明、下载进度、失败重试和重启更新入口；启动发现更新时显示非阻塞提示。
- 用户点击更新后下载安装包，验证可信发布信息及文件完整性，再由用户点击重启安装；正在压缩时禁止进入安装阶段。
- 统一桌面端、安装包和发布信息的版本号，复用 NSIS 完成覆盖安装及重新启动，保留许可证、设置和当天额度。
- 新增公开、独立于支付配置的版本信息和发布操作说明；先发布可验证的版本安装包，再发布版本信息。
- 补齐品牌图标：沿用橙色外框、白色内框、薄荷绿中心，统一程序、任务栏、窗口和安装/卸载程序的图标，并提供多尺寸资源。
- 在现有配色和布局上完善共享交互：按钮悬停/按下/禁用/键盘焦点、导入区反馈、下拉浮层阴影与展开、设置展开和窗口内容过渡；遵循 Windows 动画开关。
- 更新界面区分检查、可更新、下载、就绪和失败状态；下载进度变化不重复播放入场动效。所有操作按钮在不同文案、状态和窗口宽度下等高，同一行上下边缘对齐。

## Capabilities

### New Capabilities

- `desktop-app-update`: Windows 客户端版本检查、更新通知、下载验证、用户确认安装、发布协议，以及更新入口所用的品牌与共享界面交互要求。

### Modified Capabilities

无。当前主规格目录为空；本变更新增独立能力，与进行中的压缩和支付授权变更保持兼容。

## Impact

- 桌面端：`src/LetSmall` 中启动、主窗口、设置入口、项目版本配置及新增的更新模块。
- 视觉与交互：共享样式、轻量动效模块、图标资源和生成脚本；保持原生 Windows 窗框，不引入界面框架或改动压缩/授权协议。
- 安装：`installer/letsmall.nsi` 的版本元数据、运行进程协调、覆盖安装及更新后启动。
- 服务：`service/cloudflare` 的公开版本信息路由、版本化下载资产和发布准备脚本；不修改支付及授权协议。
- 发布：增加发布签名、公钥嵌入、版本产物校验及升级验收说明；保持 WPF/.NET Framework 4.8 和现有体积限制，不引入后台服务。
- 兼容：现有不支持更新的客户端需要手动安装一次新版。正式部署另行授权；验收不创建测试文件，文档补充不代表整体验收或发布已完成。
