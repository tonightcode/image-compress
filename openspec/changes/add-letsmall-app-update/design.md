# Design

## Context

动机见 proposal.md。变更前基线为 WPF/.NET Framework 4.8，Program 创建 MainWindow，SettingsDialog 负责输出设置。LocalStore 将设置和额度保存到独立用户数据目录，LicenseStore 使用同目录许可证和稳定设备标识。NSIS 安装到当前用户的 Programs 目录；基线支持读取原安装位置，但没有版本元数据或升级交接。

Cloudflare 的 prepare-assets.mjs 复制固定名称安装包；index.ts 的路由在处理下载前检查支付相关配置。更新服务必须独立于该配置门禁。主规格尚为空，已有桌面变更的 Focused Windows main window 要求主界面保持精简：更新入口放在设置内，启动提示只作临时状态，不增加永久业务区；后续归档时需检查两份规格的一致性。

本变更跨桌面、安装和发布服务，并包含执行下载文件的安全边界，因此创建技术设计。

## Goals / Non-Goals

**Goals:** 复用现有安装链路，以少量独立模块管理检查、下载和安装交接；原压缩和授权逻辑保持兼容。

**Non-Goals:** 定时检查、后台常驻、系统退出后通知、静默强制更新、增量补丁、多渠道、跨平台更新、自动迁移图片队列、自动降级及复杂文件事务回滚。不新增测试文件。

## Decisions

### 1. 两处事件触发，保持简单

主窗口加载后检查一次；设置内新增 Updates 入口，每次进入检查一次。更新控制器在应用会话内持有检查/下载状态，合并重叠请求，下载期间再次打开界面展示已有进度，不能重复下载。无定时器或常驻进程。启动检查超时静默结束；显式界面展示失败。检查超时默认 10 秒、响应上限 64 KiB；下载使用流式写入和超时/取消，不整包载入内存。短暂状态提示比启动模态弹窗更少干扰。

### 2. 独立的版本及可信发布信息

增加单一三段数字版本来源，构建时生成程序集版本和文件版本，向 NSIS 传入对应四段文件版本及三段 DisplayVersion，发布脚本读取同一来源。拒绝预发行及畸形版本，按数字比较，远端不高于本地时不升级。

新增固定 HTTPS `/updates/latest.json`，协议版本为 1，响应为 `payload`（Base64 的原始 UTF-8 JSON 字节）和 `signature`（Base64 签名）。payload 含 product、platform、version、publishedAt、notes、url、size、sha256；product 固定 letsmall，platform 固定 win-x64，说明按纯文本显示。对原始 payload 字节使用独立更新密钥 RSA-SHA256/PKCS#1 v1.5 签名，客户端嵌入公钥，先验签再解析；不复用许可证私钥，也不在运行时服务中保存发布私钥。

客户端仅接受配置的发布源 HTTPS 同源 URL，无凭据，不允许跳转到其他源或降为 HTTP。下载后的实际大小、SHA-256 必须与已验签信息一致；上限保持安装包 30 MiB，缺少信任配置则禁用更新执行并报告检查失败。相对仅用 HTTPS 和哈希，签名还约束安装包及其元信息的发布者，不引入更新框架。操作系统代码签名证书采购不属于本变更。

公开路由在支付配置校验前处理，但仍保留 HTTPS、方法和通用安全响应限制；仅允许 GET/HEAD。latest 使用 no-store；安装包采用不可变版本化路径 `/downloads/letsmall-<version>-win-x64.exe`。现有 `/download` 保持兼容。无账号、数据库或设备信息上报。

### 3. 下载和确认安装分开

用户点击 Update 后写入独立临时更新目录，使用 `.partial`，验证成功后转为就绪文件。取消或失败清理不完整文件并支持重新下载；不做断点续传。应用重启后重新检查，不复用未经再次验证的缓存。关闭更新窗口不取消进行中的下载，退出应用取消下载；安装前再次核对就绪文件。

就绪后提供 Restart and update；压缩任务执行期间禁用安装，并在交接前复查任务状态。确认时说明退出会清空当前内存队列；不持久化或恢复导入队列。下载期间不影响压缩。

### 4. 复用 NSIS 执行升级

升级入口将当前进程 ID、安装位置及更新模式传给已验证安装器，必须通过参数白名单和路径验证，避免拼接任意命令。先成功启动安装器再退出旧应用；启动失败时保持应用运行。安装器在写入前等待目标进程退出，检查同安装位置的其他实例；超时或占用则中止，不强杀压缩进程。

更新模式固定原安装目录，完成文件替换后才更新版本元数据和启动新版；普通官网下载安装继续保留现有交互。不修改 LocalStore 或设备标识生成规则。安装器仅写程序目录，保留用户数据。复制失败须明确提示，不启动半更新应用；允许用户重新运行完整安装包修复，不承诺复杂自动回滚。

### 5. 发布流程与验收

发布准备脚本验证程序集、安装包版本一致，计算长度与摘要，使用外部提供的私钥签名并输出版本化包和 latest。私钥不入仓库、网站资产、安装包或日志。先上传并验证版本化包，再更新 latest；旧包保留用于人工恢复。验收采用临时命令、现有检查及手工安装矩阵，不创建测试文件。

### 6. 品牌图标与共享微交互

保留现有橙色、薄荷绿、白色和布局。品牌源文件采用可编辑 SVG，生成 16、20、24、32、40、48、64、128、256 像素的 ICO，并分别接入程序集图标、WPF 窗口和 NSIS 安装/卸载图标。原先仅在窗口内容绘制品牌图形，不能替代任务栏所读取的程序图标。资源提取验证与实际任务栏目视验收分开记录，不清理用户系统图标缓存。

共享按钮使用背景叠层表达悬停和按下，不降低文字透明度；默认过渡 120 毫秒，禁用立即生效，键盘焦点使用独立轮廓。窗口内容、设置自定义路径展开采用约 160 毫秒的透明度和轻微位移过渡，避免持续动画和按帧修改布局尺寸。阴影限定在菜单等浮层，预留外侧空间避免裁切；继续使用原生窗口边框和系统阴影。

通过统一轻量动效模块读取 Windows ClientAreaAnimation，关闭时跳过内容过渡、禁用下拉淡入并将按钮过渡时长置零；设置变化后更新已打开窗口的过渡。导入区支持点击或 Enter/Space 直接打开支持多选的 Windows 文件选择框，不再展示导入类型菜单，增加悬停、拖入和键盘焦点反馈；图片行悬停有背景反馈，成功和失败仍保留文字说明，不只靠颜色区分。共享样式同时用于主窗口、设置、购买提示和更新窗口，不改变业务行为。

### 7. 更新状态与按钮几何一致性

状态区分检查中、可更新、下载中、已就绪、失败及已是最新版，使用文字、状态卡片和对应操作共同表达。检查中显示忙碌反馈，下载中显示百分比并禁止重复下载，失败保留合适的重试提示，已就绪显示 Restart and update。只在状态类别变化时过渡，不在每个下载分块更新时重播入场动画。

底部继续采用可换行布局。主操作、Cancel download 与 Later 使用相同垂直边距，避免 WrapPanel 因参与布局的外部高度不同而拉伸某个按钮。当前按钮最小高度为 38 个逻辑像素、底部边距为 8；前两个按钮右侧保留 8 的间隔，最后一个按钮无需右边距。验收比较实际布局高度与同一行的上下边缘，不只检查尺寸配置；空间不足时允许整按钮换行，不要求不同内容的按钮等宽。

2026-11-06 已用离屏 WPF 验证按钮状态、设置展开和更新状态，并渲染 100%/150%/200% 内容。按钮对齐先复现 38/46 的高度差，补齐 Later 底部边距后，新版、下载中、重试和待重启四种状态在 440/520/700 三种窗口宽度下共 12 组均为 38 高。此证据不等于实际 Windows 缩放、任务栏显示或两版安装升级已经验收。

## Risks / Trade-offs

- [现存旧客户端没有更新能力] → 首次需手动安装支持更新的版本，再进入自动发现流程。
- [覆盖过程中断电可能留下不完整安装] → 安装失败不报成功、不启动新版；提供官网下载完整包修复，用户数据独立保存。
- [多个实例阻止替换] → 安装前检查及等待，提示关闭其他实例；不扩展为全局单实例重构。
- [发布私钥丢失或泄露] → 与授权密钥隔离并离线备份；本版不设计在线密钥轮换，必要时手动安装新的可信客户端。
- [稳定版被撤回后已有更高版本用户不会降级] → 撤回只停止新分发，发布更高修复版本恢复，不自动降级。
- [已安装程序集可能无产品版本] → 实施时读取真实产物确认，首次支持更新的构建明确写入版本，避免从 manifest 的 1.0.0.0 推断已发行产品版本。

## Migration Plan

1. 配置独立发布密钥与客户端公钥，选择首个支持更新的版本号；不在规划阶段生成生产密钥。
2. 实现版本、更新模块和安装交接，再增加独立公共路由及发布脚本。
3. 以两个连续版本验证检查、下载、更新和数据保留，执行 tasks.md 的十项验收及已有构建检查，复核 30 MiB/50 MiB 体积限制。
4. 先发布版本化安装包并验证可下载，再公布 latest，官网分发支持更新的首版；既有用户手动安装一次。
5. 出现问题时撤回 latest 或恢复前一份签名信息，保持旧包可用；已升级用户使用更高版本修复包。生产发布另行取得授权。
